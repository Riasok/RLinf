# Spatial PPO: seven RL-training tasks, three held out

Paper source: https://arxiv.org/html/2510.25889 Appendix J Table11 pi0.5 Spatial.
This split is a new experiment, not the paper's full-suite reproduction.
NumPy default_rng(42).permutation(10): train IDs0,2,3,4,5,6,7; heldout1,8,9.
Exact task names and zero-based IDs are saved in logs/20260907-spatial73/split.json.
The SFT checkpoint is RLinf-Pi05-LIBERO-SFT; heldout means RL-only, not SFT-unseen.

GPUs0–3,150iterations (user budget override; paper500), batch2048,1PPO epoch, actor5e-6/critic1e-4, constant LR,
gamma.99/lambda.95/clip.2, horizon240,64envs×8rollout epochs, generate10/execute5,
denoise3, Flow-SDE noise.5. Frozen VLM, train expert and critic; noCSD/noLoRA.
Remaining optimizer defaults follow released Spatial YAML: clipgrad1,
Adam(.9,.95),eps1e-8,weight decay.01. Paper does not specify every runtime detail.
Memory adaptations: microbatch16 with gradient accumulation, rollout offload;
no bootstrap overlap. Video disabled. W&B online project rlinf-ppo-csd.

Every10iterations evaluate only heldout tasks,50fixed trials per task,150total,
20envs×8epochs with padding excluded by the existing evaluation implementation.
Save every50iterations. No heldout samples enter PPO updates. Do not select
hyperparameters on this heldout curve if treating it as a final test set.
Training supervisor stops on worker failure or low disk and cleans only its
own descendants. Existing ManiSkill job on4–7 remains untouched.

Validate: .venv/bin/python scripts/run_spatial73_20260907.py
Launch: .venv/bin/python scripts/run_spatial73_20260907.py --launch
